## 二、架构演进（关键背景）

原版经历了三次数据源转向，README 只记录了第二阶段，**文档已滞后于代码**：

| 阶段 | 方案 | 结局 |
| --- | --- | --- |
| v1 | 纯前端直连聚合 API | 早期设想，见 `3.TECH_DESIGN.md` |
| v2 | 自建 Express 后端（`server/`，3001 端口，3 平台，内存缓存） | **废弃**：后端部署 Railway（海外），大陆访问被 RST → 三卡全空 |
| v3（当前） | 前端直连 uapis.cn，6 平台 | 现行方案，链路全程国内 |

**结论**：`server/` 目录（index.js + 3 个 service + 3 个 util）已是死代码，`README.md` 通篇描述的还是 v2 架构（"后端 3001 / 三平台 / CACHE_TTL"），与实际运行方式不符。这是原版最突出的维护问题。

## 三、原版值得借鉴的功能（按价值排序）

### ★★★ 1. 金句系统 —— 项目"灵魂"所在
原版定位是「**将心注入、将爱注入**」，落地载体就是金句：

- `data/dailyQuotes.ts`：101 行内置金句库，四类调性（可爱 / 鼓励 / 认知突破 / 发疯）
- 轮换算法：10 分钟时间桶 → 第几圈(lap) → 桶内位置(pos) → 用 lap 作种子洗牌取第 pos 句。每走完一圈重洗，避免"又从头来"的循环感；同一窗口内稳定一句，刷新不闪
- 切换时 450ms 淡出淡入，不硬跳
- `components/QuoteBottle.tsx`（339 行）：**隐藏款彩蛋**——点顶部金句文字弹出漂流瓶，用户可投句，localStorage 存 `mini-hot-hub:user-quotes`（上限 100 条，FIFO 淘汰）
- 内置库与用户投句"均匀混合、不加权"轮换

> 本地目前完全没有这层。这是两版**气质差距**的主要来源——本地是"功能正确的热榜"，原版是"有人味的站"。

### ★★★ 2. 已读即隐藏 + 浏览垃圾桶
- 点击热点 → 写入今日记录 → **该条从榜上消失**，第 11 名自动补位
- 数据层保留 50 条（`ITEM_LIMIT = 50`），卡片层过滤已读后取满 10 条并**重编号 1-10**，保证无空号
- 自然日 00:00 自动重置（存 `date` 字段，读取时比对）
- **FLIP 动画**（Web Animations API）：已读隐藏后剩余条目平滑上移、第 11 名从下方淡入。用「相对列表容器」的 top 而非视口 top，避免页面滚动污染位移差
- 彩蛋：当日看过 ≥40 条，列表底部浮现「今日已看 N 条，我也是有底线哒～」
- `useVisitDays.ts`：累计访问天数，垃圾桶里显示「已陪你翻 N 天热点了~」

> 本地做的是「收藏」（主动加），原版做的是「已读即隐藏」（被动消）。两者其实互补：**已读即隐藏解决"看过的热搜反复出现"的痛点，收藏解决"想留住"的需求**。

### ★★ 3. 移动端细节打磨（本地目前较弱）
- **长标题两次点击**：手机无 hover，第一次点标题只弹出完整标题气泡预览，第二次才跳转。桌面 hover 直接预览、一次点击即走
- 全局唯一气泡：跨 6 平台共享，同一时刻最多一个，跨平台自动互斥
- **滚动位置恢复**：`sessionStorage` + `localStorage` 双写（微信等 WebView 常清空 session），10 分钟内有效。从文章返回不会被打回顶部
- `onMouseDown` 阻止默认：避免点击抢焦点引发的"跳到标题"滚动，键盘 Tab 聚焦不受影响

### ★★ 4. 诚实的平台脚注（对应其 PRD 的「P3 诚实优先于漂亮」）
卡片底部按平台显示真实差异说明：
- B站：「B站榜单刷新得比较慢，不是不更新哦~」
- 小红书：「是比B站更恐怖的更新速度（吓）」
- 头条：「头条暂未提供热度值，按官方榜单顺序展示~」

`updatedAt` 用上游真实的 `update_time`，**不用本端 fetch 时间**——不把"一小时前的数据"伪装成"刚刚更新"。

### ★ 5. 其他
- 入场动画 `EntryOverlay`（114 行）：「将心注入·将爱注入」1 小时 1 次
- 平台拓展开关：逐平台显隐，localStorage 持久化，全部隐藏时显示温和空态
- 温和文案体系：4 处错误/空态统一调性（「这一刻的热榜去溜达了，稍等片刻再回来看看吧～」等）
- 三主题切换（暖黄 / 浅绿 / 深黑），CSS 变量 + `data-theme`

## 四、原版的坑（本地必须避免）

1. **无前端缓存** —— `api/hot.ts` 里没有任何缓存代码，每次刷新 6 个请求直打 uapis.cn。免费层配额 2000 次/天/IP，10 次刷新就烧掉 6%。本地的 localStorage 10 分钟缓存 + 退避重试明显更优，**不要回退**。
2. **无错误重试** —— 网络抖动/429 直接进错误态且不自愈。本地已有指数退避，保持。
3. **文档与代码脱节** —— README 371 行通篇讲 Express 后端，实际早废弃。本地 `docs/项目上下文.md` 有"最后更新"时间戳，习惯更好，继续维护。
4. **仓库塞满构建产物** —— 107 个 `dist_bak_*` 目录、30MB，真源码只有 247K。本地已在 `f44e9da` 清理过构建产物，且 `.gitignore` 到位。
5. **激进的版本策略** —— React 19 / Vite 8 / TS 6 全上最新，漂移风险高。本地锁版本（React 18 / Vite 5 / TS 5 / Tailwind 3.4）更稳。
6. **无测试无 lint 无 CI** —— 只有 `oxlint` 一个 script。本地 22 个单测 + ESLint + CI 是实打实的优势。
7. **死代码未清理** —— `server/` 整个目录仍在仓库。

## 五、结论与建议

**总体判断**：本地 Mini_hot 在**工程化、平台覆盖、数据层健壮性**上已明显领先原版；原版的核心优势在**产品温度与移动端交互细节**，这部分恰恰是纯技术视角容易漏掉的。

**建议优先级**：

| 优先级 | 动作 | 理由 |
| --- | --- | --- |
| P0 | 引入「已读即隐藏」+ 浏览记录 | 直接解决热榜类应用的核心痛点，且本地 10 平台更吃这个 |
| P1 | 引入金句系统（内置库 + 轮换算法） | 决定产品气质，成本可控（101 行数据 + 约 60 行逻辑） |
| P1 | 移动端：长标题两次点击 + 滚动位置恢复 | 本地已有 Capacitor 壳，移动体验应补齐 |
| P2 | 平台脚注诚实提示 | 30 行以内，但对"可信度"提升明显 |
| P2 | 三主题改为三主题（补一个暖色外的主题） | 可选，看是否要对齐原版气质 |

**不建议照搬**：
- 前端直连无缓存 —— 本地已有更优方案
- React 19/Vite 8/TS 6 升级 —— 收益低、风险高
- server/ 后端 —— 已经证明是弯路
