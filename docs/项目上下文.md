## 一、项目概述

**Mini_hot** 是一个聚合微博/知乎/B站/抖音/小红书/今日头条六大平台实时热榜的单页应用。数据来自公开第三方接口 `uapis.cn`，UI 完全原创（参考原站暖色治愈系氛围，但文案/排版/设计全新）。

**技术栈**：Vite 5 + React 18 + TypeScript 5 + Tailwind CSS 3.4（锁版本安装，避免漂移）

**当前状态**：
- ✅ 6 平台数据正常加载（接口 CORS 全开放、配额缓存策略已生效）
- ✅ 热度值归一化（覆盖裸数字/中文后缀/w缩写/空值）
- ✅ 三态渲染（加载/错误/空态），单平台挂不影响其他
- ✅ 单测覆盖（15/15 pass）
- ✅ TypeScript 零错误
- ✅ 生产构建通过（9.9KB CSS / 151KB JS）

## 二、技术决策记录

### 2.1 API 接口
- **端点**：`https://uapis.cn/api/v1/misc/hotboard?type={weibo|zhihu|bilibili|douyin|xiaohongshu|toutiao}`
- **CORS**：反射式 AC AO（任意 Origin 均回显，localhost/生产域名都可通过）
- **限流**：`ip-daily 2000/天/IP` + `visitor-quota 1500 credits`，耗尽即停（429）
- **返回结构**：
  ```json
  {
    "type": "weibo",
    "update_time": "2026-08-25T15:16:49.000Z",
    "list": [
      {
        "index": 1,
        "title": "在韩失联女生已遇害",
        "url": "https://s.weibo.com/weibo?q=...",
        "hot_value": "11468191",
        "extra": {}
      }
    ]
  }
  ```
- **关键发现**：
  - 各平台 `hot_value` 格式差异大（见 §2.3）
  - 头条 `hot_value` 可能为空字符串
  - 条目数不统一（bilibili 100 / xhs 20 / 其他 50）

### 2.2 热值归一化
`src/utils/formatHeat.ts` 处理 6 种形态：
| 平台 | hot_value 示例 | 输出 |
|------|----------------|------|
| 微博 | `"11468191"` | `1146.8万` |
| 知乎 | `"1798 万热度"` | `1798万` |
| B站 | `"2142239播放"` | `214.2万` |
| 抖音 | `"11821659"` | `1182.2万` |
| 小红书 | `"920.8w"` | `920.8万` |
| 头条 | `""` | `--` |

**实现细节**：先用正则提纯数字 + 识别单位词（w/W/万/亿），再按量级分档（≥1亿→亿、≥1万→万、其余→千分位）。浮点精度用 `Math.round(num*10)/10` 修正。

### 2.3 竞态处理陷阱
**踩坑记录（2026-08-23）**：
- 初期用共享递增计数器 `reqSeqRef` 做过期判断，但 6 平台并发时只有 seq 最大的平台（头条）能成功，其他 5 个被误判"过期"丢弃。
- **根因**：`seq !== reqSeqRef.current` 逻辑对所有平台共享计数器失效。
- **修复**：移除共享 seq，改用 `signal.aborted` 判断（AbortController 已足够）。

### 2.4 Tailwind 配置坑
**踩坑记录**：
- `tailwind.config.js` 的 `content` 未包含 `./src/**/*.css`，导致 `@apply bg-cream` 等类在 index.css 里使用但未被扫描生成。
- **现象**：body 底色丢失，页面"裸 HTML"感。
- **修复**：content 加入 `'./src/**/*.css'`。

## 五、已知限制

1. **接口配额**：免费层 ip-daily 2000 次/天，部署到公网需关注配额消耗（建议加缓存 + 降级提示）
2. **无后端 BFF**：前端直连存在跨域依赖，若接口方变更 CORS 策略会受影响
3. **数据时效**：接口更新时间约 1-15 分钟不等，非实时
